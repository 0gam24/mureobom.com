# 품질 게이트 채점 루브릭 (100점, 게이트 85점)

quality-gate 에이전트가 발행 전 모든 글을 채점한다. 작성자(writer)와 분리된
컨텍스트에서 레드팀 관점으로 채점하며, 글을 직접 고치지 않고 판정만 한다.

기준 문서: [docs/prompts/google-content-master-prompt-v4.md](prompts/google-content-master-prompt-v4.md)
PART 41(FINAL QUALITY AUDIT)·42(FACT CHECK)·43(REDUNDANCY AUDIT)·47(DECISION TEST).
이 루브릭은 그 감사 항목을 mureobom 파이프라인 점수로 옮긴 것이다.

> 배경: 2026년 상반기 Google이 이 사이트를 "대량 생산·차별화 없는 콘텐츠"로 분류해
> 노출이 0에 수렴했다. 게이트는 "틀리지 않은 글"이 아니라 "이 글이 아니면 얻을 수 없는
> 정보가 있는 글"만 통과시킨다. 애매하면 감점이다.

## 1. 사실 정확성·출처 검증 — 30점
- [10] 글의 핵심 수치·기간·자격 요건이 1차 출처(법령·국세청·고용노동부·공단·금융당국·
  정부24·복지로)와 일치. 조문 번호·기관명·정책명이 실제와 일치
- [8] 모든 출처 URL이 실재하고(WebFetch로 표본 2개 이상 실확인) 해당 내용을 실제로 담고 있음
- [6] 정보 기준일·적용 연도가 본문에 명시되고 현재 유효. "최신"·"현재"를 확인 없이 쓰지 않음
- [6] 사실/해석/추정/가상 사례가 구분됨. 추정을 사실처럼, 가상 사례를 경험처럼 쓰지 않음.
  추측·과장 표현 부재("~로 알려져 있다", "무조건", "100%" 감점)
- 치명 결격(즉시 0점·KILL): 존재하지 않는 제도·조문·수치 서술, 위조 출처·URL, 허위 1인칭 경험,
  실재하지 않는 전문가 검수 사칭

## 2. 정보 이득·독창적 가치 — 25점
- [10] Information Gain 요소 2개 이상: 자체 계산 예시, 조건별·연도별·가구별 차이표, 예외 조건,
  실무 마찰 지점(서류·기한·중복 적용·대리 신청), 시나리오 분기, 타임라인, 교차 출처 종합
  (하나만 있으면 5점, 없으면 0점)
- [8] 해석 레이어: 출처 대조에서 나온 판단 기준·주의점·자주 틀리는 지점. 출처 요약 짜깁기만
  있으면 0. "출처만 읽어도 알 수 있는 내용"의 반복이면 0
- [7] brief의 `차별화:` 각도가 본문에 실제로 구현됐고, 같은 클러스터 기발행 글과 다른 질문을
  해결함(카니발리제이션 없음)

## 3. 검색의도 충족·구조 — 20점
- [8] 첫 화면: summary·keyPoints·첫 문단에서 핵심 답·핵심 수치·가장 중요한 조건이 즉시 보임.
  첫 문단이 summary의 재진술이면 -3
- [6] 구조가 검색의도 유형(제도/비교/계산/문제해결/변경사항)에 맞고, 각 H2가 실제 질문을
  해결함. 개수 채우기용 H2·의미 없는 섹션이 있으면 감점. 절차·자격·금액은 표 또는 단계로
  스캔 가능
- [6] 결론이 본문 재나열이 아니라 행동 계획(무엇을 어디서 확인·비교할지)임. FAQ가 있다면
  본문 복사가 아닌 후속 질문·예외·경계 조건임(FAQ가 없어도 감점하지 않음)

## 4. 정책·문체 — 15점
- [6] YMYL 프레임: 조언·권유 없음, 정보·절차만. "신청하세요" 대신 "신청할 수 있다".
  금리·한도·수익률 단정, 특정 기관 추천 없음
- [5] AdSense·제목 정책: 클릭 유도·과장 제목 없음(무조건·총정리·이것만 보면 끝 등), 금지 주제
  비접촉, 일반정보 고지 유지, 본문에 없는 내용을 제목·summary가 약속하지 않음
- [4] 문체: 긴 줄표(—·–) 없음, 화살표(→) 단계 표현 1회 이하, 상투구("정리하면"·"결론적으로"·
  "첫째/둘째"·"핵심은 N가지") 없음, 고정 소제목("정리 — 한 줄로"·"흔한 오해") 상투 반복 없음

## 5. 중복·내부링크 — 10점
- [5] 사이트 내 중복 없음(`automation/briefs/_published_slugs.txt` + `src/content/answers/*.md`
  프론트매터 title·targetQuery grep) **그리고** 글 내부 중복 없음: 체크리스트류 블록 1개 이하,
  같은 명제·같은 숫자·같은 표의 재등장 없음, 표를 문장으로 재복사하지 않음
- [5] 관련 내부링크 2개 이상(실재하는 `src/content/answers/{slug}.md`만), 앵커가 대상 글 내용을
  설명함("여기"·"관련 글" 앵커는 감점)

## 판정 규칙
- 85점 이상: PASS → 발행 진행
- 70~84점: REVISE → 감점 사유를 writer에 반환, 리비전 1회만 허용. 재채점 후 85 미만이면 KILL
- 70점 미만 또는 치명 결격: KILL → 발행 폐기, 사유를 장부에 기록
- **하루 1편 원칙**: KILL이면 그날은 발행 0편으로 끝낸다. 대체 글을 급조하지 않는다
  (잘못된 발행 1건이 발행 0건보다 사이트에 해롭다)

## 출력 포맷 (quality-gate 에이전트 필수 준수)
```json
{
  "verdict": "PASS | REVISE | KILL",
  "score": 0,
  "breakdown": {"accuracy": 0, "unique_value": 0, "intent": 0, "policy": 0, "dedup_links": 0},
  "fatal": false,
  "issues": ["감점 사유를 구체적 위치와 함께"],
  "checked_sources": ["실확인한 출처 URL"]
}
```
